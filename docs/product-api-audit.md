# 客户端精修与 API 核查

日期：2026-09-15。范围：账户概览、收款账户、USDT 充值、USD 付款、企业资料和安全设置。结论：当前原型覆盖选定业务主流程，但不能视为已完成生产 API 接入或全量交互验收。

## 核查依据

- PayFi-API-Reference-v1.2.2 2.md：接口与状态的主要依据。
- PayFi-KYC-Dictionary-And-Rules-v1.2.1.md：企业字段、国家字典、材料规则。
- PayFi-Payee-Dictionary-And-Rules-v1.2.1.md：六种收款账户模板及用途字典。
- 文件来源：用户提供的 `/Users/evanqi/Downloads/接口文档v1.2.2/`。

### 文档冲突

1. KYC 字典 2 节允许 AVAILABLE/STABLE 重新审核；v1.2.2 的 5.2 节仅允许 AVAILABLE + false 更新，禁止重新提交审核，其他状态拒绝。本原型当前只提供 UNAVAILABLE + true 首次/驳回重提，不开放审核通过后的编辑。
2. Payee 字典旧版表示创建响应有双编号；v1.2.2 的 8.2 节明确创建响应仅 payee_no/status。完整资料须通过详情查询，不得假定创建响应包含银行字段。
3. SN 按 v1.2.2 的 2.5 节，不能先裁剪空白再提交。由应用生成并保存；重试必须复用。

## 本轮修正

- 修复充值入账、付款冻结/完成时将已有 8 位余额截断至 2 位的问题。请求金额仍最多 2 位；余额运算用 BigInt 保留 8 位。
- 修复 CLOSED 和未知支付通道被企业资料页误判为已开通。
- 按 KYC 字典将 BAP 标注为“经营场所照片”、CORPORATION 标注为“股份有限公司”。
- 日期验证真实日历日期，网址验证协议和 host，国家选择以文档 ISO 字典为候选，中文可搜索。
- 校验字段失焦错误，提供字段级 aria-invalid/错误关联；KYC 下一步校验当前步骤。删除 UBO 时仅移除对应附件并重排后续附件索引。
- 银行表单按收款企业/银行账户分组，地址等长字段跨列；禁止修改被有效结算引用的收款账户。
- MFA 等待期间锁定付款/银行提交，阻止重复操作，银行修改冻结输入快照；组件卸载后停止后续本地业务变更。
- 充值详情将地址优先展示，补充平台/合作方费用、正常到账流水、异常退款流水。未取得地址时不给出可用于充值的伪造地址。
- 付款详情补充费用拆分、更新时间、渠道、备注和打款凭据区域；过期报价不能确认。
- 列表补充每页 20 条分页及结果计数，筛选改变回到第一页；修复 table-wrap 缺少横向滚动导致列被挤压的问题。
- 移除冗余页眉标签、孤立图标及付款申请中的固定费率文案，增强次要文本可读性。

- 24 笔充值：等待、部分到账、已完成、终止，包含正常/异常流水。
- 8 笔付款：待确认、处理中、完成、取消、终止。

## 尚不能声称完成的部分

- 没有接入真实后端。商户归属、权限、HMAC、SN 持久化/重试、文件真实上传/类型校验、回调乱序/验签、数据持久化、余额和状态权威同步仍须服务端实现。
- 银行模板是按文档预置的字段集合。正式接入必须读取 templates 返回的 regex/enum_values/max_length；HK RTGS SELF 账号正则及各场景名称/地址正则无法从静态文档完整还原，不做“全部字段完全符合线上模板”的承诺。
- 当前搜索是前端本地筛选。接口的 SN 为精确筛选，NO 应走详情接口；银行名称模糊搜索未见专门接口参数，联调时不能将当前 includes 逻辑直接当远程 API 能力。日期筛选和服务端分页尚未接入。
- 当前汇率和费用是本地固定计算；正式接入应读 reference / fees / query-rate 返回值。打款凭据来自详情，临时 URL 过期后应重新查询。
- 未覆盖的 API 功能包括海外企业、多证件类型、正常/异常退款发起、审核通过后 KYC 更新。这些没有冒充已实现功能。
- 未完成全量交互验收：移动导航背景隔离/焦点约束、全部模态退出动画与脏表单离开确认、服务端字段错误精确定位、网络错误/迟到响应、多层 MFA 完整浏览器操作、读屏、真实触屏键盘、200% 缩放及所有低高度场景。需后续逐项验收，不能称为“最优”或“生产就绪”。
